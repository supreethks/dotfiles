Review ONLY the provided git diff and any attached screenshots / Lighthouse notes / viewport captures.

Read and apply:
- Severity: Blocker|Critical|Warning|Tip (Blocker/Critical fail the gate)
- Every finding MUST cite: Nielsen Hn | WCAG SC x.y.z | named UX law | deceptive-pattern name

Evaluate strictly for websites:

1. Information architecture & hierarchy
   - Brand/primary headline/CTA clear in first viewport; one job per section (Nielsen H8)
   - Landmark structure: single h1, no skipped heading levels (WCAG SC 1.3.1, 2.4.6)
   - Nav predictable; mobile menu usable with keyboard (WCAG SC 2.1.1)

2. Responsive & layout integrity
   - No horizontal overflow at ~375 / 768 / 1440 (Blocker if page-wide)
   - Touch targets on mobile ≥ 24px (WCAG SC 2.5.8); comfortable ≥ 44px preferred
   - Images have alt or are decorative; broken images flagged

3. Accessibility floor
   - Text contrast ≥ 4.5:1; UI components ≥ 3:1 (WCAG SC 1.4.3 / 1.4.11)
   - Visible focus; form labels; error text not colour-only
   - Status messages available to AT where dynamic UI exists (WCAG SC 4.1.3)

4. Conversion & ethics
   - Primary CTA contrast and placement; avoid competing equal-weight CTAs
   - No deceptive patterns (confirmshaming, hidden costs, fake urgency)
   - Performance UX: huge unoptimized hero media that delays LCP → Critical if evidence shows it

5. Adversarial probes
   - Empty CMS fields, long copy, zoom 200%, keyboard-only pass, print/contrast modes if relevant

Output format:
- If no Blocker and no Critical: end with exactly `VERDICT: APPROVED`
- Else numbered SEVERITY/WHERE/BEFORE/AFTER/WHY blocks
